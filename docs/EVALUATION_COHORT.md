# 评测用户与请求覆盖修正

2026-11-25 的服务器乐器域数据审计发现：旧版配置选取 200 位有验证或测试事件的用户，其中只有部分用户有测试标签（确切人数见审计 `test_labels`，仅凭覆盖率不能确定分母）；请求构造按用户依次生成全部模板，800 条总预算只覆盖前 19 人。799 条请求中，51 条的正例仍可行，但仅来自 6 位独立用户。测试正例目录覆盖率为 21.9%，空集合请求为 106 条。这是数据支持与预算分配的诊断，不是推荐效果结果。

## 修正

1. `exp1.data.prepare` 新增 `evaluation_split`：`test`、`validation`、`either`。未指定时保留旧版 `either` 行为，三域正式配置显式使用 `test`。在有足够合格用户时，200 位入选者均有测试标签。用户按训练历史资格和测试事件存在抽取，不读取正例商品身份、目录归属或可行性作为入选条件。目录外正例继续保留。训练目录和所有训练序列的构建规则不变。
2. `build_requests` 先分配无筛选基线，再按轮次给每位用户分配一个结构模板，并依据用户次序轮转起始模板。约束与对应随机对照整体计入预算。当前 800 条预算足以给 200 位用户各一条无筛选基线及至少一组结构/随机对照，剩余预算继续下一轮。每个用户不再拥有全部模板。
3. 审计新增每个约束族的有效正例请求数、有效正例独立用户数，以及请求池的标签用户数。正例信息仅用于事后统计，不参与规则或请求选择。
4. 三域两阶段的当前配置使用 `runs/<domain>-experiment{1,2}-v2`。旧输出保留。原始评论与元数据不必重新下载；冻结用户、标签和请求必须在新目录重新准备。

## 解释边界

修正请求分配不能保证 HR/NDCG 的有效样本充足，也不会保证目录覆盖率上升。紧品牌、规格和交叉筛选可能仍只有少量可行正例。应按约束族、强度分别报告有效独立用户数和置信区间；空可行集合保留，单独统计输出不足与候选不足。OracleRecall 仍可评价没有可行历史正例但具有非空候选集合的请求。

不得按测试正例落入目录、满足筛选或是否命中来挑选用户、改写正例或调整规则。若某个细分条件的有效样本不足，报告该局限或在事先明确的新协议中扩大标签无关的用户样本和请求预算，不以重复同一用户的约束请求替代独立用户。

## 服务器重新准备

更新到包含此修正的提交后，保留旧运行目录并执行：

```bash
CUDA_VISIBLE_DEVICES="" python -u scripts/run_suite.py \
  --experiment 1 --datasets musical --prepare-only --resume
```

查看 `runs/musical-experiment1-v2/audit.json` 中的 `test_labels`、`test_catalog_coverage`、`constraints.unique_users`、`constraints.family_unique_users`、`constraints.family_positive_feasible_requests` 和 `constraints.family_positive_feasible_users`，再决定正式比较的统计支持范围。
