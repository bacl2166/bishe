# 实验二：编码如何影响真实生成模型的推荐与搜索

本实验复用实验一冻结的目录、用户历史、请求和商品编码。在每套编码上训练一个相同主体结构的 Transformer 生成推荐模型，检验实验一观察到的编码与约束关系，是否出现在模型实际学习到的 token 概率中。它是统一模型下的编码模块比较；各论文原生系统的训练方法和额外模块不在这一实验中复现。编码适配的范围见 [TOKENIZERS.md](TOKENIZERS.md)。

## 数据与训练

三个子域为 Musical Instruments、Amazon Fashion、Appliances，规模控制与缺失属性说明见 [DATASETS.md](DATASETS.md)。三域具有独立目录与模型，不混合训练。实验二从 `source_run` 读取 `prepared.json`、`catalog.json`、`requests.json` 和 `encodings/<name>-<seed>/mapping.json`，不重新划分数据或重新生成约束。

训练样本是训练序列的每个严格前缀及其下一件商品。用户历史使用共同的商品 ID 嵌入，经 Transformer encoder 编码；因果 decoder 根据历史和已经生成的 token 预测下一个 token。训练目标是包含 EOS、忽略 padding 的完整词表交叉熵。用户筛选条件在评测请求阶段加入，训练时不加入。模型结构、teacher forcing、变长编码、保存和恢复见 [GENERATOR.md](GENERATOR.md)。

统一主体结构不意味着参数量完全相同：编码的词表和最长路径不同，会改变输出层和位置嵌入的大小。每个模型记录词表、路径长度、参数量、训练时间和验证损失。正式配置采用三组编码种子与三组模型种子的交叉组合，每个域有 `12×3×3=108` 个生成模型，三个域共 324 个。建议先用离线检查或单域缩小配置确认服务器环境，再开展全量实验。

## 两种评分目标

对请求的同一个可行集合 A，模型以用户历史 h 为条件。商品路径包含末尾 EOS：

`s_original(i|h) = sum_t log p(token_t | h, token_<t)`。

`preserve` 搜索屏蔽没有可行商品后代的路径，保留完整词表的原始 log 概率，不改变叶子评分目标。

`local` 在每个前缀处，仅对具有可行商品后代的下一 token 重新归一化，再沿路径求和。因此它的精确排序可能与原始评分不同。完整词表包含 PAD/BOS、过早 EOS、目录外路径等无效输出；即使 `no_filter` 请求，local 的目录合法性屏蔽也可能改变原始目标。解释请求级约束的增量影响时，必须同时查看 `no_filter` 对照，不能把所有差异都归于用户筛选。

所有模式都包含 EOS，均不使用长度归一化。可变长度编码的短路径倾向属于本实验评分约定的一部分，应结合码长分析，不直接解释成某个编码整体优越。

## 实际搜索与精确排序

实际搜索调用模型的完整词表概率，逐层展开可行前缀，以 beam 宽度和候选子节点数限制预算。已完成商品放入独立结果池，按完整路径分数排序返回。没有整层剩余预算时停止，返回已经完成的商品并标记预算耗尽；不会超过节点上限。`scored_nodes` 是评分的候选子节点数，`expanded_nodes` 是展开的非终止前缀数，它们不是模型 FLOPs。实际延迟单独计时，在 CUDA 上同步；每次搜索清空用户历史缓存，计入历史编码和可行树构造，不计模型载入、训练或精确诊断时间。

在任何模型训练和评估前，按请求 ID 与固定种子选定最多 80 条诊断请求，保存为 `diagnostic_requests.json`。抽样不读取正例内容、模型结果或约束是否命中。三域分别抽取；同一域所有编码与种子共享该集合。

先运行实际搜索，再对诊断请求的**全部可行商品**求完整路径分数。共享前缀只需计算一次，但每条可行商品路径均被覆盖，不使用 beam、节点预算或参考推荐结果裁剪。分别枚举原始评分和 local 评分并排序，得到**这个模型自己的**两份精确参照。精确评分不会提供给搜索算法。诊断全集大小仍需记录；80 条请求不是 80 件候选商品。

## 指标与解释

所有请求输出 HR@10、NDCG@10（仅以正例仍可行为分母）、正例可行率、可行输出率、返回不足率、候选不足率、节点数与实际延迟。请求的历史正例表示后续评论交互，不等价于用户看到模拟筛选条件后的真实替代购买；因此不对不可行正例伪造替代标签。

只有预先指定的诊断请求输出以下参考指标；其他请求记为 `null`，不会混入参考指标分母：

| 字段 | 含义 | 用于回答的问题 |
|---|---|---|
| `exact_hr`, `exact_ndcg` | 原始评分的精确可行 Top-K | 该编码与模型本身是否能把正例排在前面？ |
| `own_exact_hr`, `own_exact_ndcg` | 当前处理模式的精确可行 Top-K | 当前评分目标的理论排名如何？ |
| `oracle_recall` | 实际结果覆盖原始精确 Top-K 的比例 | 与原始目标的总偏离有多大？ |
| `own_oracle_recall` | 实际结果覆盖当前模式精确 Top-K 的比例 | 有多少偏离来自有限搜索？ |
| `objective_topk_overlap` | 两种精确 Top-K 的重合率 | 局部归一化改变了多少目标商品？ |
| `distribution_kl` | 两种路径分数在 A 上归一化后的 KL(original‖own) | 评分分布变化有多大？ |
| `lost_hit_rate` | 原始精确命中、实际未命中的请求占原始精确命中请求的比例 | 原本能命中的正例是否丢失？ |
| `own_lost_hit_rate` | 当前目标精确命中、实际未命中的对应比例 | 正例是否在当前目标的搜索中丢失？ |
| `positive_original_rank`, `positive_own_rank` | 可行正例在两份完整排序中的名次 | 评分变化和搜索各影响哪一步？ |
| `search_score_loss`, `own_search_score_loss` | 两个目标下，精确 Top-n 平均 log 分数减实际 n 件商品的平均 log 分数 | 漏掉商品的模型评分差距有多大？ |

最后两个分数损失用 `n=min(K, 实际返回数)` 比较等长集合，空输出记为 null，返回不足另报。分数损失不能独立替代返回不足率；不同模型的绝对 log 分数也不能直接比较高低。`first_pruned` 记录可行商品首次被 beam 剪掉的深度；节点预算提前停止时，仅标记预算耗尽，不将未探索商品伪记为 beam 剪枝。

`summary.json/csv` 按编码、模型种子、编码种子、约束和预算汇总。HR/NDCG 使用全部合格请求，`diagnostic_requests` 给出每组精确诊断样本数。用户级 bootstrap 在诊断子集上计算实际 NDCG 减原始精确 NDCG 的区间。`paired_comparisons.json/csv` 与随机平衡编码配对比较，同一请求与用户对齐；参考指标只比较共同的诊断请求。各随机种子分别报告，正式论文再综合种子间均值和变异，不将同一用户的多条约束请求当成独立用户。

先看 exact HR/NDCG 的跨编码差异，再看 own OracleRecall 随预算的变化，最后看原始与当前精确参照的差异。搜索更接近模型 Top-K，未必提高真实正例的 HR/NDCG；两者必须同时报告。

## 运行与恢复

在仓库根目录配置 Python 3.10+ 与 `requirements.txt`，按 [DATASETS.md](DATASETS.md) 下载数据。正式配置要求 CUDA；CPU 小试需另存配置并将设备改为 cpu。现有实验一的旧配置仍保留，三域配置用于新的匹配规模实验。

```bash
# 先检查端到端流程，无需下载数据；不产生正式效果结论
python scripts/smoke_exp2.py

# 三域先做数据审计
python scripts/run_suite.py --experiment 1 --prepare-only

# 完成实验一以及全部编码映射（已准备的目录需要 --resume）
python scripts/run_suite.py --experiment 1 --resume

# 实验二：共享实验一目录、请求与编码映射
python scripts/run_suite.py --experiment 2 --resume

# 单域运行
python -m exp2 --config configs/experiment2_musical.json --resume
```

完成输出位于 `runs/<domain>-experiment2/`。`models/` 保存最佳权重及训练记录，`rows/` 保存逐请求结果，顶层保存汇总、配对比较、诊断请求和来源 manifest。原始数据、模型、运行结果不提交到 Git。

`--resume` 复用完整模型 checkpoint 和完成的模型结果；若某模型训练中断且尚无完整 checkpoint，则重训该模型；若解码中断，则复用该模型并重做它的请求评估。并不从中途 optimizer 状态恢复。指纹覆盖代码、配置、冻结数据、请求、所用编码映射，以及 Python、NumPy、PyTorch 和 CUDA 构建版本；发生变更须使用新输出目录，避免拼接不同版本结果。严格拒绝来源目录与输出目录相同、缺少映射、目录不一致和历史被改写的请求。

旧版 `experiment1.json` 的乐器配置上限为 5000，三域新配置改为 3000；即使输出目录名称相同，也不能续接旧实验结果。保留旧结果并给新实验一配置指定新 `output` 时，也须同步修改对应实验二配置的 `source_run`；实验二自身也应使用新输出目录。程序遇到来源指纹不匹配会明确停止，不自动删除已有结果。
